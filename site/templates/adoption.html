publishing to tianguis

publishing is automated via milpa publish, which packs your source, pushes an OCI artifact, cosign-signs it, and POSTs to the dispatch endpoint. tianguis verifies the signature and commits the new entry to the index.

end-to-end: tag-push to installable in ~60 seconds. no human review, no PR queue.

github actions (the easy path)

drop this into .github/workflows/publish.yaml in your repo: 

name: publish

on:
  push:
    tags: ["v*"]

jobs:
  publish:
    uses: coreyleavitt/tianguis/.github/workflows/publish.yaml@v1
    with:
      name: my-package           # must match your milpa.kdl
      version: ${{ github.ref_name }}
    permissions:
      id-token: write   # cosign keyless signing
      contents: read    # checkout
      packages: write   # push OCI artifact to GHCR

push a tag (git tag v1.0.0 && git push origin v1.0.0) and within ~60 seconds your version appears here. that's it.

optional inputs

  • registry — OCI registry ref (default: ghcr.io/<owner>/<repo>:<version>). any OCI v2 endpoint works: ghcr, dockerhub, quay, lscr.io, Harbor, self-hosted Zot.
  • dispatch-url — for staging/self-hosted dispatch endpoints (default https://dispatch.tianguis.dev).
  • dry-run: true — pack + push + sign without committing to the index. use this once before going live to verify the OCI artifact + Rekor entry look right.

any other CI

the publishing protocol is a four-step shell pipeline; any CI whose OIDC issuer is trusted by Sigstore Fulcio can publish. confirmed working: GitLab CI, Codeberg/Forgejo/Woodpecker, Buildkite, Google Cloud Build, CircleCI.

see the any-CI guide for a worked GitLab CI example + the raw protocol you can wire into anything.

not currently supported

  • sourcehut builds — sourcehut's OIDC issuer isn't in Sigstore's federation (yet). cosign keyless can't mint a signing certificate. revisit when upstream federation expands.

what the trust chain looks like

  1. your CI: milpa publish packs source deterministically, pushes to OCI registry, cosign-signs the artifact (signature lands in Rekor).
  2. tianguis dispatch (Scaleway, stateless): verifies your CI's OIDC token. cross-checks the identity claim against the declared repo URL. returns workflow_dispatch to the tianguis commit pipeline. no cryptographic decisions here — the serverless function is structurally not in Sigstore's trust set.
  3. tianguis commit workflow (GitHub Actions): independently runs cosign verify-blob on the OCI artifact, recomputes the content_hash, merges the new entry into index.kdl, attests the commit decision to Rekor under its own workflow identity, pushes.
  4. this site rebuilds within seconds. your version is live.

third-party monitors can audit by comparing Rekor entries (queryable by workflow identity) against the contents of index.kdl in the repo. divergence between the two is a publicly-visible alarm.
