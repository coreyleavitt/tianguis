specifications

tianguis is meant to be implemented by anyone — the index format, dispatch protocol, and attestation model are specified in the repository's docs/ directory. these are the load-bearing documents:

format + transport

  • index-format.md — the KDL grammar for index.kdl. canonical encoding rules. JSON projection semantics. strict-schema validation.
  • rfc-distribution-and-publishing.md — why OCI artifacts. why cosign. why content addressing. trust model end-to-end.
  • rfc-registry.md — the high-level registry design. why tianguis exists as separate from nim-lang/packages.

adoption

  • adoption/github.md — copy-paste GH Actions setup
  • adoption/any-ci.md — the four-step protocol for any Sigstore-federated CI

endpoints

  • https://tianguis.dev/index.kdl — canonical index (KDL)
  • https://tianguis.dev/index.json — JSON projection of the same data
  • https://dispatch.tianguis.dev/v1/publish — author-side publish endpoint (POST + OIDC bearer)
  • https://dispatch.tianguis.dev/healthz — liveness check

reference implementations

  • milpa — Python reference consumer. resolves named deps via tianguis, fetches via OCI, verifies content_hash. github.com/coreyleavitt/milpa
  • tianguis — the registry itself. Go dispatch endpoint + Nim vendor-bot + static site builder. github.com/coreyleavitt/tianguis

related

  • Sigstore — the attestation substrate
  • oras — the OCI artifact CLI tianguis uses for transport
  • KDL — the canonical index encoding
